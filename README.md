# vBios — личный кабинет VPN для SHM

React + TypeScript + Vite + Mantine. Кабинет для покупки, оплаты и подключения VPN через API SHM.

## Возможности

- Главная: баланс, подписки, предстоящие платежи и инструкция подключения.
- Мой VPN: выбор тарифа, заказ, состояние услуг, ссылка подписки и QR-код.
- Баланс: существующие способы оплаты SHM и промокоды.
- Операции: история пополнений и списаний.
- Уведомления: текущие состояния услуг; это не серверный журнал событий.
- Поддержка: обращения, переписка и вложения при поддержке серверного API.
- Профиль: контакты, Telegram ID, безопасность и подтверждённая привязка Telegram.
- Тёмная/светлая темы и мобильная версия. Управление HWID удалено из страницы услуг.

## Быстрый запуск из исходников

Требуется Node.js 20.19+ или поддерживаемая более новая версия.

```bash
npm ci
cp .env.example .env
npm run dev
```

Настройте VITE_* в .env. Не добавляйте в VITE_* токены Telegram, Remnawave и другие серверные секреты: эти значения доступны посетителю браузера.

```bash
npm run build
npm run preview
```

Сборка создаётся в dist. Для запросов к API нужен доступный SHM и корректный прокси /shm. Демо-данные в исходники не встроены.

## Запуск Docker-образа

```bash
cp .env.deploy.example .env
# Измените SHM_URL на реальный адрес API, APP_NAME на название кабинета.
docker compose pull client
docker compose up -d client
```

Клиент слушает 127.0.0.1:3001. Настройте внешний HTTPS reverse proxy вашего домена на этот адрес. SHM_URL должен быть доступен из контейнера. Не переносите пример Compose поверх серверной конфигурации без сравнения: у существующей установки могут быть другие сети, volumes и имя сервиса.

Runtime-параметры контейнера APP_NAME, SHM_URL и другие поддерживаемые entry.sh значения передаются через environment. Серверный .env сам по себе не становится частью браузерного приложения. VITE_* применяются во время сборки, APP_NAME и SHM_URL — при запуске контейнера.

## CI/CD

Build and publish image запускается на main, тегах v* и вручную. Pull request собирает образ без публикации. Main публикует ghcr.io/dev-vbs/vbios-client:latest и :main; коммиты получают тег sha-<short>; релиз v1.0.0 получает :v1.0.0.

Публикация использует GITHUB_TOKEN, отдельный PAT обычно не нужен. Для существующего пакета GHCR проверьте доступ Actions репозитория к пакету. Для публичного скачивания установите видимость пакета Public. Для приватного образа на сервере требуется docker login ghcr.io с правом read:packages.

Telegram workflow независим от сборки. Его TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID задаются в Actions Secrets. Ошибка 401 означает недействительный токен; публикация образа от этого не становится успешной или неуспешной автоматически — это отдельный workflow.

## Требования к серверу и ограничения

Этот репозиторий содержит клиент, не ядро SHM. Он не устанавливает серверные маршруты автоматически.

Профиль использует существующие API пользователя, email и Telegram. Предварительный блок сессий и настроек уведомлений удалён. Telegram OIDC требует серверной конфигурации callback и данных бота.

Новые страницы баланса/операций используют существующие API. Опрос ответов тикетов в App.tsx пока отключён (useTicketPoller(false)); не считайте отсутствие индикатора подтверждением отсутствия новых ответов.

## Проверки

npm run build проходил в рабочей среде. Браузерная проверка нового дизайна выполнена на тестовых ответах API, включая desktop 1440px, mobile 390px, баланс и открытие тарифов. Реальные платежи, OAuth, серверные сессии и создание тикетов не подтверждены. Предупреждение Vite о размере bundle не блокирует сборку.
